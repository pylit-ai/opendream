# 00-platform-thesis.md

## Thesis
OpenDream should not ship as “a better memory note file.”
It should ship as a **memory control plane** that is:
- verified,
- bandwidth-disciplined,
- relation-aware,
- auditable,
- and able to accept semantic work from multiple execution owners without losing truthfulness.

## Why this exceeds note-oriented systems
- typed canonical state instead of markdown-only truth
- verify-before-assert for concrete claims
- contradiction/supersession relations as first-class runtime state
- procedural memory as a separate capability
- generated-only startup/index views
- release scorecards and memory-hurt budgets
- cross-runtime execution support instead of a single-tool monoculture

## Product posture
The release should present OpenDream as:
- one canonical memory/control plane,
- multiple supported execution surfaces,
- one shared review and evidence model.

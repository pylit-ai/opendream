# 440-memory-platform-superiority-release-bundle

## Why

OpenDream already has the foundations of a serious memory runtime: typed durable records, layered stores, transcript-native dreaming, semantic learned-context surfaces, automation projections, benchmark adapters, release verification, and thin framework adapters. A separate memory-excellence bundle is also raising the bar on verified claims, grep-first transcript probing, contradiction relations, reconciliation, generated-only views, procedural memory, and release scorecards.

That is the right base. But a release that aims to exceed note-oriented memory systems still fails if operators cannot tell:
- which runtime actually owns semantic execution,
- when extra provider credentials are required,
- how framework-native background execution feeds back into OpenDream,
- how feature mining and radar jobs run across local and delegated paths,
- and whether the stronger memory-excellence guarantees still hold when execution is owned by Codex, Claude, or Cursor.

The next release therefore needs one integrated bundle that does all of the following at once:

1. Preserve thin-adapter governance and canonical-core discipline.
2. Make semantic execution ownership explicit: local direct-provider vs delegated vendor runtime vs deterministic fallback.
3. Prefer “no extra key when possible” without implying unsupported generic OAuth reuse.
4. Add vendor-native semantic execution surfaces that can feed validated outputs back into OpenDream.
5. Make feature mining, bug radar, fix radar, and semantic refresh runnable across those surfaces.
6. Tie all of the above into the memory-excellence scorecard so the release proves it is better, not merely more convenient.

## Goal

Ship a release-ready memory platform that combines:
- memory-excellence guarantees,
- unambiguous semantic setup and execution ownership,
- vendor-native delegated semantic execution for Codex, Claude Code, and Cursor,
- validated delegated ingest,
- multi-layer automation playbooks that stay truthful,
- and release evidence that proves OpenDream is a verified, bounded, relation-aware memory control plane rather than a note folder or vendor-specific wrapper.

## What Changes

- add an explicit semantic execution-policy layer on top of current semantic mode
- add a setup wizard and status/read-model that recommend the strongest supported path with “no extra key when possible”
- add first-class execution surfaces for:
  - Codex account-backed local trusted execution
  - Claude scheduled-task delegated execution
  - Cursor automation delegated execution
- add delegated semantic envelope + ingest contracts
- add framework-specific feature-mining / radar / semantic-refresh scaffolds
- reconcile docs, FAQ, playbooks, benchmark docs, and release notes with actual runtime ownership and trust boundaries
- integrate the new execution surfaces with the memory-excellence bundle so verified writes, graph relations, reconciliation, and review UX remain authoritative regardless of who ran the semantic pass
- extend release evidence so the same excellence scorecard is demonstrably maintained across direct-provider and delegated execution modes

## Non-goals

- generic borrowing of arbitrary vendor OAuth sessions into OpenDream
- weakening the canonical-core / thin-adapter boundary
- replacing typed canonical memory with vendor-owned markdown or raw transcripts
- shipping benchmark/comparison docs that depend on unofficial implementation claims
- requiring every user to create new API keys even when a supported account-backed or vendor-delegated path exists
- forcing a full knowledge-graph database into the release

## Success criteria

- operators can run one setup command and get an explicit recommendation for:
  - direct-provider,
  - codex-account,
  - claude-scheduled-task,
  - cursor-automation,
  - or deterministic-only,
  with reasons and trust notes
- delegated semantic runs return structured, validated envelopes that enter OpenDream through auditable proposal/event paths only
- feature mining / bug radar / fix radar / semantic refresh can be scaffolded for direct-provider and delegated modes
- docs and status surfaces always show who owned the semantic execution
- release verification proves the memory-excellence scorecard stays within threshold budgets across supported execution modes
- the release positions OpenDream as a cross-runtime, verified memory control plane that exceeds note-oriented memory systems on truthfulness, observability, procedural reuse, and operational clarity

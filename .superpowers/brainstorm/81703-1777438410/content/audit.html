UI Audit — OpenDream Observe

Findings from screenshots of Overview, Runs, Memories, Retrievals, Reviews, Settings, Graph at 1440×900

Top 12 issues holding the app back

  1. Page header eats ~22% of viewport on every route. Scope path + "Advanced Semantic Mode" dropdown + 3-line explainer paragraph + "About this dashboard" + timestamp — all persistent global chrome.
  2. Verbose body copy explains what each page is ("This page is the operator-facing summary of…"). Dilutes content; teaches once, not every load.
  3. Empty right panes on Runs ("Consolidation Inspector"), Retrievals ("Retrieval Explainability") waste 40% of screen until selection. No empty-state design — just "Select a run." text.
  4. Always-expanded filter rows: Search + Sort + Dir + Page size + Time window + Advanced filters disclosure — 4 rows of controls before any data.
  5. Sidebar section labels ("CATALOG", "THIS WORKSPACE", "TRACE", "AUDIT AND TOOLS") add noise. 11 nav items don't need 4 grouping headers.
  6. Stat cards oversized on Memory Surface — 4 huge cards for 4 numbers, then immediately a verbose paragraph repeating context.
  7. Inconsistent typography: ALL-CAPS micro-labels mix with sentence-case headings, inline code in body, and wide muted help text. No clear hierarchy ramp.
  8. Color/chip system overloaded: status pills (completed/contested), edge-kind chips (supersedes/conflicts_with), node-type tags (memory/review/run) all use distinct colors but no shared semantic system. Reads like a debug view.
  9. Text-as-icon: "JSON" "CSV" export buttons, "Hide first steps", "Bookmark this", "Other dashboards" — all should be icon-first with tooltips.
  10. Inconsistent dates: "Apr 28, 2026, 9:54:44 PM" vs "SUN, 3/29/2026" vs "8:33 PM" mixed within one page.
  11. Command palette exists in DOM but hidden from primary UI. No global ⌘K affordance — discoverability of power features = zero.
  12. Brand presentation weak: "OD" in muted gray pill + "OBSERVE" eyebrow + "OpenDream" wordmark stacked. No color, no weight, looks like placeholder.

Pattern: what YC-tier observability tools do differently

Linear, Vercel, Stripe, Sentry, Datadog all share these moves:

What they do

  • Tight 56–64px global header with workspace switcher + ⌘K + user, nothing else
  • Sidebar = icons at rest, labels on hover/expand. ~48px wide collapsed
  • Empty states with illustration + 1 primary CTA, never just "Select a row"
  • Filters collapsed into a single bar with chips for active filters
  • One typography ramp: 11/13/14/16/24, sentence case everywhere
  • Two-color status system (success/warn/danger) + neutral; everything else monochrome
  • Density toggle; default to comfortable, power users go compact
  • Help text = one-tap (?) not body paragraph
  • Master-detail uses split-pane only when both have content; otherwise full-bleed list

What OpenDream does

  • ~180px header with explainer prose on every page
  • 240px sidebar with 4 section labels + always-visible names
  • "Select a run." in a 700px-wide empty right pane
  • 3 filter rows visible by default per page
  • ALL CAPS, sentence case, code, muted text mixed without rhythm
  • ~12 distinct chip colors with no shared semantic key
  • Single density, leans verbose
  • Multi-paragraph descriptions inline above data
  • Empty right pane permanent; no graceful degradation

Proposed direction (high level)

Three-phase plan, each phase ships independently:

🪒

Phase 1 — Subtract

Kill global explainer paragraph, collapse filters, remove sidebar section labels, replace text buttons with icons, unify date format. ~2 days. Biggest perceived-quality jump per hour.

🎨

Phase 2 — System

Design tokens (spacing/type/color scales), unified chip semantics, empty-state component, command palette surfaced (⌘K), brand mark refresh. ~3 days. Makes future work fast & consistent.

🚀

Phase 3 — Polish

Master-detail collapse-when-empty, density toggle, keyboard nav, micro-animations, illustrated empty states, graph canvas fix + redesigned controls. ~3 days.
